# 特种设备检测模块 UI/UX 设计方案 (RuoYi-Vue 版)

## 1. 设计概述
本方案旨在为“特种设备检测”业务打造一套高效、严谨且符合 RuoYi 框架规范的 B 端界面。
核心设计理念：**紧凑高效、任务闭环、风险可视**。

- **适用框架**: Vue 2 + Element UI (RuoYi-Vue)
- **视觉风格**: 科技蓝主色调，紧凑型信息密度。
- **布局模式**: 左侧导航 + 顶部 Tab + 内容区（支持分栏/全屏）。

---

## 2. 信息架构与菜单建议
建议在 `src/views` 下新建独立目录 `specialEquipment`，与现有业务隔离。

```text
特种设备检测 (Special Equipment)
├── 委托管理 (Entrustment)
│   ├── 委托登记 (Create/Edit) - 独立复杂表单
│   └── 委托列表 (List) - 核心工作台
├── 样品台账 (Sample Ledger)
│   └── 样品管理 (List) - 以委托为视角，展开看样品，支持批量收样
├── 检测任务 (Tasks)
│   ├── 我的任务 (My Tasks) - 检测员视图
│   └── 任务分配 (Assignment) - 负责人视图
├── 原始记录 (Records)
│   ├── 录入 (Entry) - 支持全屏/分步
│   └── 列表 (List)
├── 报告管理 (Reports)
│   ├── 报告编制 (Preparation)
│   ├── 报告审核 (Audit) - 左右分栏高效审核
│   ├── 报告批准 (Approval)
│   └── 报告发放 (Distribution)
└── 基础配置 (Settings)
    ├── 原始记录模板
    ├── 报告模板
    └── 样品参数配置
```

## 3. 核心页面布局设计

### 3.1 委托列表 (高效工作台模式)
**设计目标**: 让受理人员一眼看到风险，快速处理流转。

**布局结构**:
```text
+---------------------------------------------------------------+
| [搜索区] 委托单号 | 委托单位 | 状态 | 业务类型 | [搜索] [重置]  |
| ------------------------------------------------------------- |
| [工具栏] [+新增] [批量流转] [导出]      [风险图例: 🔴超期 🟠临期] |
| ------------------------------------------------------------- |
| [表格区 - 紧凑模式]                                            |
| [] 单号     | 单位   | 业务 | 剩余 | 状态   | 受理人 | 操作     |
| [] 2024... | XX公司 | 气瓶 | 🔴-2 | 待流转 | 张三   | [流转]...|
| [] 2024... | YY工厂 | 阀门 | 🟢 5 | 待分配 | 李四   | [分配]...|
| ...                                                           |
+---------------------------------------------------------------+
```
**关键交互**:
- **风险列**: 使用 `el-tag` + 图标显示剩余天数。小于 0 天标红，0-3 天标橙。
- **快捷操作**: 表格右侧操作列直接放「流转」「分配」「查看进度」按钮（Icon 形式），减少点击层级。

### 3.2 样品台账 (委托-样品层级)
**设计目标**: 快速确认收样状态，无需频繁跳转详情。

**表格交互 (Tree Table / Expand)**:
```text
[v] 委托单号: 2024-SE-001 | 委托单位: XX公司 | 样品总数: 5
    +-- [表格内嵌] ---------------------------------------------+
    | 样品名称 | 编号   | 标配 | 铭牌 | 锈蚀 | 配件 | 操作      |
    | 气瓶A    | S-01  | [√]  | [√]  | [x]  | [√]  | [修改]    |
    | 气瓶B    | S-02  | [√]  | [√]  | [√]  | [√]  | [修改]    |
    +-----------------------------------------------------------+
```
**实现方案**: 使用 Element UI Table 的 `type="expand"` 或树形数据结构，默认展开当前处理中的委托。

### 3.3 审核/批准工作台 (左右分栏沉浸式)
**设计目标**: 减少页面跳转，实现“点一条、审一条、过一条”的流水线操作。

**布局结构**:
```text
+----------------------+----------------------------------------+
| [左侧: 待办列表]       | [右侧: 详情预览区]                       |
| [搜索...]            | [顶部: 状态条 + 审核操作栏]               |
|                      | (通过) (退回-必填原因) (上一条) (下一条)    |
| 1. XX委托 - 待审      | ---------------------------------------|
|    2024-01-12        | [原始记录表单 / PDF 预览区域]             |
|                      |                                        |
| 2. YY委托 - 待审      | 字段1: [ Value ]                       |
|    2024-01-11        | 字段2: [ Value ]                       |
|                      | 图片:  [ img1 ][ img2 ]                |
| 3. ZZ委托 - 待审      |                                        |
| ...                  |                                        |
+----------------------+----------------------------------------+
```
**实现方案**:
- 左侧 `width: 300px` 列表，支持分页。
- 右侧 `flex: 1` 详情区。
- “退回”点击后弹出 Dialog，强制填写原因。

## 4. 关键组件选型与规范

1.  **流程追踪 (Process Track)**
    -   **位置**: 详情页顶部或 Drawer 抽屉。
    -   **组件**: `el-steps` (顶部简略) + `el-timeline` (详情抽屉)。

2.  **文件/图片上传**
    -   **需求**: 原始记录手动上传图片。
    -   **组件**: 封装 `ImageUpload`，支持粘贴上传、拖拽上传、点击预览大图。

3.  **打印/导出**
    -   **方案**: 后端生成 PDF 流，前端 `iframe` 预览或 `window.open` 下载。
    -   **打印**: 使用 Print.js 或浏览器原生打印（需编写 `@media print` CSS 隐藏导航栏和按钮）。

4.  **表单验证**
    -   所有必填项加红色星号 `*`。
    -   检测期限需校验“晚于当前时间”。
    -   数值型字段（如压力、通径）限制输入类型。
