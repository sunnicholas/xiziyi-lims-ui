一、需求背景：为什么要改？

1.1 原有方案的问题

原有 PdfCertCleanConverter.smartCrop() 是对整页PDF渲染图片做全局白色裁剪：扫描左/右/下三个方向的纯白像素，裁掉白边。这导致：

  • ❌ 只能出一张图：整页Excel只能裁剪出一张大图，无法按区域拆分
  • ❌ 无法区分多个逻辑区块：比如检测记录中有"外观检查区"、"尺寸测量区"、"性能测试区"三个独立区块，原方案只能把它们混在一张图里
  • ❌ 空白裁剪不精确：如果表格中间有大片空白，smartCrop 无法感知"中间空白"，只能按最外围边界裁剪

1.2 新需求

用户在Excel模板中用 VBA 宏绘制虚线边框（xlDash）围成多个矩形区域，保存时希望每个区域单独截一张图。

三、如何在Excel中画虚线框（VBA宏）

3.1 方法一：VBA宏（推荐，模板中使用）

在Excel中按 Alt+F11 打开VBA编辑器，插入模块，粘贴以下代码：

' codes fix from xzyPC: 选中区域后运行此宏，自动画虚线边框
Sub AddDashedBorder()
    With Selection.Borders(xlEdgeLeft)
        .LineStyle = xlDash          ' 虚线
        .Weight = xlMedium           ' 中等粗细
        .ColorIndex = xlAutomatic
    End With
    With Selection.Borders(xlEdgeTop)
        .LineStyle = xlDash
        .Weight = xlMedium
        .ColorIndex = xlAutomatic
    End With
    With Selection.Borders(xlEdgeBottom)
        .LineStyle = xlDash
        .Weight = xlMedium
        .ColorIndex = xlAutomatic
    End With
    With Selection.Borders(xlEdgeRight)
        .LineStyle = xlDash
        .Weight = xlMedium
        .ColorIndex = xlAutomatic
    End With
End Sub

四、核心算法：虚线框检测原理

4.1 算法总体流程

1
构建边框矩阵（4个二维布尔数组）
遍历所有单元格，读取 CellStyle，判断 Top/Bottom/Left/Right 4个方向的边框是否为虚线样式。
如果 BorderTop ∈ DASHED_STYLES → hasDashedTop[row][col] = true
同理：hasDashedBottom、hasDashedLeft、hasDashedRight
2
逐行扫描"上边界"连续段
从上到下，对每一行扫描 hasDashedTop[row][*]，找到连续的虚线Top列段。
例：第3行中，列B到列F都有 Top虚线 → 一个"上边界"段：startCol=B, endCol=F, row=3
3
验证左上角的 Left 边界
检查 startCol 列在当前行是否有 Left虚线。
有 → 确认是矩形左上角；没有 → 跳过（可能只是水平线，不是矩形）
4
向下扫描找"下边界"行
从当前行往下一行行找：startCol到endCol所有列都有 Bottom虚线的行 → 就是下边界。
同时验证 endCol 列从 topRow 到 bottomRow 每行都有 Right虚线 → 确认是矩形右边界
5
记录矩形区域 + 去重
四边都验证通过 → 创建 CellRangeAddress(topRow, bottomRow, startCol, endCol)
检查是否与已发现的区域相同 → 不重复 → 加入结果列表

4.2 示意图

Excel 单元格结构（虚线边框示意）：

     A    B    C    D    E    F    G
 1
 2  ┌────────Top虚线──────────┐
 3  │ Left虚线  区域1内容  Right虚线│
 4  └───────Bottom虚线─────────┘
 5
 6  ┌────────Top虚线──────────┐
 7  │ Left虚线  区域2内容  Right虚线│
 8  └───────Bottom虚线─────────┘

算法检测结果：
  区域1: CellRangeAddress(第2行, 第4行, B列, F列)
  区域2: CellRangeAddress(第6行, 第8行, B列, F列)
🔍 为什么算法能正确区分两个相邻区域？
因为算法以 Top虚线 + Left虚线同时存在 作为"左上角"的识别标志。区域1的第2行B列有Top+Left虚线 → 左上角。然后在找下边界时，第4行有Bottom虚线 → 下边界。接着从第5行扫描，跳过没有Top虚线的行，到第6行又发现B-F有Top虚线 → 下一个区域的开始。两个区域互不干扰。

五、区域截图生成流程

5.1 为什么用"临时文件法"？

有两种方案可以实现区域截图：

方案方法优点缺点
像素坐标法 将整张Excel转为一张大图 → 根据列宽/行高计算像素坐标 → getSubimage裁剪 只需1次LibreOffice转换 列宽单位(1/256字符宽)和行高(磅)到600DPI像素的映射误差大，不同平台不一致
临时文件法 ✅ 对每个区域创建临时XLSX（只含该区域单元格） → LibreOffice转PDF → 600DPI渲染 → PNG 精确、可靠、跨平台一致 多个区域时需要多次LibreOffice调用（性能稍差）

5.2 单区域截图步骤

因为临时Excel只有一个Sheet且只有该区域的单元格，转换后PDF就是该区域的精确呈现

十、常见问题

问题 解答
虚线框画了但检测不到？ 1. 确认是虚线（VBA: xlDash），不是实线（xlContinuous）
2. 确认四个边都有虚线（不是只画了部分边）
3. 用 Excel 打开，右键单元格→设置单元格格式→边框，确认边框样式是虚线
4. 查看日志：detectDashedBorderRegions 输出的检测结果
虚线框在Sheet2上检测不到？ 当前实现只检测第一个Sheet（createRegionOnlyWorkbook 中 srcWorkbook.getSheetAt(0)）。
如果你的虚线框在Sheet2上，需要修改代码指定 Sheet 索引。
或者确保虚线框在第一个 Sheet 中。
区域截图与原始Excel排版不一致？ 可能原因：临时Excel中没有复制列宽和行高。
查看 createRegionOnlyWorkbook() 是否调用了 setColumnWidth 和 setHeight。
当前实现已包含列宽和行高的复制。
截图中有多余的白色边距？ 正常现象。临时Excel渲染时四周会有少量白边，cropWhiteBorders() 会自动裁剪。
如果白边仍然很多，可以减小 MARGIN 常量（当前为10像素）。
多个虚线框截图很慢？ 因为每个区域都要走一次"创建临时Excel→LibreOffice转换→PDFBox渲染"的流程。
如果区域数量较多（>5个），可以考虑以下优化：
1. 合并小的相邻区域
2. 或者改用"像素坐标计算法"（但精度会降低）
通常检验记录中只需要2-4个区域，性能可以接受。
保存后的图片文件名是 region_1.png 而不是 page_1.png 了？ 这是预期行为。新模式下每个区域生成 region_N.png（N从1开始）。
数据库存储的JSON中路径会相应变化，前端展示需要适配这个命名变化（或者不改前端，因为都是通过JSON读取路径）。
