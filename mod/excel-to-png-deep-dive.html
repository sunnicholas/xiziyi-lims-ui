📊 2. 第一步：ExcelSheetToPdfUtils — Excel → PDF

2.1 为什么要用LibreOffice而不是POI直接转？

Apache POI虽然能读写Excel，但它渲染PDF的能力极差——合并单元格错位、边框丢失、字体不一致。而LibreOffice是完整的办公套件，它的Calc组件打开Excel后能完美还原格式，再通过JodConverter调用LibreOffice的服务模式把文件"另存为PDF"，实现了1:1格式还原。

⚠️ Ubuntu下的关键区别：Windows版使用Office COM对象，而Ubuntu依赖LibreOffice。LibreOffice必须安装并作为服务运行。这是该代码能在Linux跑的核心前提。

2.2 静态初始化块：启动LibreOffice服务（仅一次）

private static class OfficeHolder {
    private static final ExcelSheetToPdfUtils INSTANCE = new ExcelSheetToPdfUtils();

    static {
        try {
            // LocalOfficeManager.builder() 会在本地启动一个LibreOffice进程（后台模式）
            officeManager = LocalOfficeManager.builder()
                    .install()            // 💡 自动查找系统已安装的LibreOffice
                    .taskExecutionTimeout(60000L) // 💡 单个转换任务超时60秒
                    .build();
            officeManager.start();       // 🔥 启动！此后LibreOffice进程常驻内存

        } catch (Exception e) {
            log.error("❌ LibreOffice 启动失败", e);
        }
    }
}

第二步：处理公式 → 转为静态值

LibreOffice打开Excel时，如果单元格包含公式（如 =SUM(A1:A10)），它不会自动计算。所以代码先把所有公式的结果静态化（转为字符串值），否则LibreOffice转PDF时会显示 #VALUE! 或空值。

【代码】处理公式单元格
for (int rowIndex = sheet.getFirstRowNum(); rowIndex <= sheet.getLastRowNum(); rowIndex++) {
    XSSFRow row = sheet.getRow(rowIndex);
    for (int cellIndex = row.getFirstCellNum(); cellIndex < row.getLastCellNum(); cellIndex++) {
        XSSFCell cell = row.getCell(cellIndex);
        if (cell.getCellType() == CellType.FORMULA) {
            CellType cachedType = cell.getCachedFormulaResultType();
            if (cachedType == CellType.STRING) {
                finalValue = cell.getStringCellValue();     // 字符串公式结果
            } else if (cachedType == CellType.NUMERIC) {
                double num = cell.getNumericCellValue();
                String formatStr = cell.getCellStyle().getDataFormatString();
                if (formatStr != null) {
                    DecimalFormat df = new DecimalFormat(formatStr);
                    finalValue = df.format(num);            // 💡 保留Excel原始数字格式
                } else {
                    finalValue = String.valueOf(num);       // 无格式直接转
                }
            }
            // 🔑 关键操作：把公式单元格强制改为文本类型
            cell.setCellType(CellType.STRING);
            cell.setCellValue(finalValue);
        }
    }
}

3.1 核心配置参数

【配置】渲染参数
private static final int RENDER_DPI      = 600;    // 🔥 600DPI（打印级超清）
private static final int MARGIN           = 20;     // 裁剪后保留的边距（像素）
private static final int WHITE_THRESHOLD  = 254;    // 255是纯白，254是容忍度（近似白色也算空白）
参数值含义为什么选这个值
RENDER_DPI600渲染分辨率（每英寸像素数）证书需要打印级清晰度。300DPI=屏幕清晰，600DPI=打印级超清。生成的图片文件更大，但文字边缘锋利。
MARGIN20裁剪后边距完全裁剪到内容边会让证书"顶格"显示不美观。保留20像素边距保证视觉效果。
WHITE_THRESHOLD254白色容忍度PDF->PNG渲染后，纸张背景不是完美的255纯白（PDFBox渲染有轻微色差）。254容忍一小块近似白也算空白区域。
为什么是600DPI？如果你只做屏幕预览，300DPI就够了。但这个项目的PNG最终会嵌入到证书的Word模板中，打印后需要清晰。600DPI是"证书打印质量"的标准选择。代价是每张图片约2-5MB。

3.2 convertPdfPages —— 主方法逐行解析

【代码】PDF转PNG主流程
public static List<String> convertPdfPages(String pdfPath, String outputDir) {
    List<String> resultPaths = new ArrayList<>();

    // ① 使用PDFBox加载PDF文档
    try (PDDocument document = PDDocument.load(new File(pdfPath))) {
        PDFRenderer renderer = new PDFRenderer(document);  // PDFBox渲染器
        int totalPages = document.getNumberOfPages();      // 总页数
        log.info("PDF总页数：{}", totalPages);

        // ② 确保输出目录存在
        File dir = new File(outputDir);
        if (!dir.exists()) dir.mkdirs();

        // ③ 逐页处理
        for (int pageIndex = 0; pageIndex < totalPages; pageIndex++) {
            // 🔥 按600DPI将PDF页面渲染为Java BufferedImage（位图）
            BufferedImage fullImage = renderer.renderImageWithDPI(pageIndex, RENDER_DPI);

            // 🔥 智能裁剪：去掉上下左右空白区域
            BufferedImage croppedImage = smartCrop(fullImage);

            // ④ 写出PNG文件
            String outputPath = new File(outputDir, "page_" + (pageIndex + 1) + ".png").getAbsolutePath();
            ImageIO.write(croppedImage, "png", new File(outputPath));
            resultPaths.add(outputPath); // 收集所有生成的图片路径
        }
        return resultPaths;
    }
}

3.3 smartCrop —— 智能裁剪算法详解

这是"把图片多余空白去掉"的核心算法。PDF每次渲染会带上整张纸的背景（全是白色），不裁剪的话图片会上下左右留大片空白，难看不美观。

算法图示

     ┌─────────────────────────────┐  ← y=0 (图片顶部)
     │         (大量空白)            │
     │  ┌─────────────────────┐    │  ← left=150 (第一个非白像素列)
     │  │                     │    │
     │  │   实际内容区域        │    │
     │  │  (证书数据表格等)     │    │
     │  │                     │    │
     │  └─────────────────────┘    │  ← bottom=1200 (最后一个非白像素行)
     │         (大量空白)            │
     └─────────────────────────────┘  ← y=1800 (图片底部, height=1800)

     裁剪后：
      left - MARGIN  = 130
      right + MARGIN = 1450
      bottom + MARGIN = 1220
      → 最终尺寸 = 1320 × 1220（内容撑满，留20px边距）

findLeftBorder —— 找到左边第一个有内容的像素列

【算法】从左向右逐列扫描
private static int findLeftBorder(BufferedImage image) {
    int w = image.getWidth();
    int h = image.getHeight();
    for (int x = 0; x < w; x++) {           // ← 从左向右
        for (int y = 0; y < h; y++) {       //  ← 这一列从上到下
            if (!isWhite(image.getRGB(x, y))) // 🔑 找到第一个不是白色的像素
                return x;                     // 返回列号 → 这就是"左边界"
        }
    }
    return -1;  // 整张图全白（不太会发生）
}

findBottomBorder —— 从下向上找底部边界

注意：代码没有做findTopBorder（顶部裁剪从y=0开始）。这是因为证书PDF的顶部通常就是内容起始位置，保留了顶部。

isWhite —— 判断一个像素是否是"白色"

【算法】白色判断
private static boolean isWhite(int rgb) {
    Color c = new Color(rgb);
    return c.getRed() >= 254
        && c.getGreen() >= 254
        && c.getBlue() >= 254;
    // 🔑 R、G、B 三个分量都 ≥ 254 → 判定为白色
    // （254而非255，因为PDFBox渲染的纸张背景不是完美纯白）
}

public static String normalizeOriginalFilePath(String filePath) {
    // 1. 去掉 Web 前缀 "/profile/original/"
    String cleanPath = filePath.replace("/profile/original/", "");
    //    例如: "/profile/original/2026/05/test.xlsx" → "2026/05/test.xlsx"

               .toString().replace("\\", "\\\\");
}

4.4 getPdfPath — Excel路径→PDF路径

【代码】FilePathUtil.java 第14~34行
public static String getPdfPath(String excelPath, String suffix) {
    String lowerPath = excelPath.toLowerCase();
    String[] excelExtensions = {".xlsx", ".xlsm", ".xls"};
    for (String ext : excelExtensions) {
        if (lowerPath.endsWith(ext)) {
            // 1. 去掉扩展名
            int lastDot = excelPath.lastIndexOf('.');
            // 2. 拼接 suffix + ".pdf"
            return excelPath.substring(0, lastDot) + suffix + ".pdf";
        }
    }
    return excelPath + suffix + ".pdf";
}

package com.xzy.common.utils;

import com.fasterxml.jackson.databind.ObjectMapper;
import org.junit.jupiter.api.Test;
import java.io.File;
import java.nio.file.Files;
import java.nio.file.Paths;
import java.util.*;

public class FullConversionTest {

    // 📐 这个方法模拟了 OfficeOnlineApi.excelToImgFile() 的完整逻辑
    @Test
    public void testFullPipeline() throws Exception {
        // ====== 准备参数（模拟 Controller 接收的参数） ======
        String excelPath = "/home/xiziyi/uploadPath/original/test/test_record.xlsx";

        // ====== 1. 生成PDF路径 ======
        String dataPdfPath   = FilePathUtil.getPdfPath(excelPath, "_data");
        String resultPdfPath = FilePathUtil.getPdfPath(excelPath, "_result");

        // ====== 2. 创建输出目录 ======
        File originalFile = new File(excelPath);
        String parentDir = originalFile.getParent();
        String resultImgDir = parentDir + File.separator + "result";
        Files.createDirectories(Paths.get(resultImgDir));

        System.out.println("=== Step1: Excel → PDF ===");
        System.out.println("  结果页PDF: " + resultPdfPath);
        System.out.println("  数据页PDF: " + dataPdfPath);

        // ====== 3. Excel → PDF ======
        boolean r1 = ExcelSheetToPdfUtils.convertSingleSheet(excelPath, resultPdfPath, "结果页");
        boolean r2 = ExcelSheetToPdfUtils.convertSingleSheet(excelPath, dataPdfPath, "数据页");
        assert r1 && r2 : "❌ Excel→PDF 转换失败";

        // ====== 4. PDF → PNG ======
        List<String> resultImages = PdfCertCleanConverter.convertPdfPages(resultPdfPath, resultImgDir);
        assert !resultImages.isEmpty() : "❌ 没有生成PNG图片";

        System.out.println("\n=== Step2: PDF → PNG ===");
        resultImages.forEach(p -> System.out.println("  ✔ " + p));

        // ====== 5. 路径转换（模拟 Service 层的逻辑） ======
        // 本地路径 → Web路径
        String dataWebPath = PathConverter.convertToOriginalWebPath(dataPdfPath);
        System.out.println("\n=== Step3: 本地路径 → Web路径 ===");
        System.out.println("  数据PDF-本地: " + dataPdfPath);
        System.out.println("  数据PDF-Web:  " + dataWebPath);

        // 多图片路径整体转换（模拟 convertPathsToWebJson）
        List<String> webImageList = resultImages.stream()
            .map(PathConverter::convertToOriginalWebPath)
            .toList();
        System.out.println("  结果图片(本地):");
        resultImages.forEach(p -> System.out.println("    " + p));
        System.out.println("  结果图片(Web):");
        webImageList.forEach(p -> System.out.println("    " + p));

        // ====== 6. 模拟存入数据库的JSON ======
        String resultImgJson = new ObjectMapper().writeValueAsString(webImageList);
        System.out.println("\n=== Step4: 存入DB的JSON ===");
        System.out.println("  result_file_url = " + resultImgJson);
        System.out.println("  data_pdf_url    = " + dataWebPath);

        System.out.println("\n✅ 完整链路测试通过！");
    }
}

🔧 8. 常见故障排查手册

8.1 LibreOffice启动失败

【日志特征】
❌ LibreOffice 启动失败
❌ 转换工具未初始化
原因解决方案
LibreOffice未安装sudo apt install libreoffice libreoffice-headless -y
headless包缺失sudo apt install libreoffice-headless -y（Docker容器必须）
soffice不在PATHexport PATH=$PATH:/usr/lib/libreoffice/program/ 加到 ~/.bashrc

8.2 PNG中文变成方块□□□

【日志特征】
转换成功，但打开PNG后中文全部是口口口
原因解决方案
Ubuntu缺少中文字体sudo apt install fonts-wqy-microhei fonts-noto-cjk -y
LibreOffice没有识别字体重启应用（Office进程会重新读取系统字体列表）

8.3 Permission Denied（文件写入失败）

【日志特征】
java.io.FileNotFoundException: /home/xiziyi/uploadPath/original/...
(Permission denied)
原因解决方案
应用用户没有目录写入权限sudo chown -R appuser:appuser /home/xiziyi/uploadPath/
（把 appuser 替换为实际运行应用的用户）
父目录不存在sudo mkdir -p /home/xiziyi/uploadPath/original/

8.4 转换超时（60秒超时）

【日志特征】
❌ 单个Sheet转换失败
java.util.concurrent.TimeoutException

超时阈值: taskExecutionTimeout(60000L) — 60秒
原因解决方案
Excel文件过大（几百MB）检查Excel是否有不必要的数据，或调大超时：.taskExecutionTimeout(180000L)（3分钟）
服务器内存不足LibreOffice进程吃内存，检查可用内存：free -h

8.5 图片模糊/字体发虚

原因解决方案
DPI太低确认 RENDER_DPI = 600 没有被改过
裁剪参数不对确认 MARGIN = 20，太小会导致内容贴边
