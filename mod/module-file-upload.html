📤 文件上传规则与路径生成详解

从配置到磁盘：文件是怎么被存到服务器上的？路径是怎么拼出来的？

1. 一切从配置开始

在 application.yml 中有一个核心配置项，它决定了所有文件的"家"在哪：

# application.yml xzy: profile: /Users/sunnicholas/uploadPath ← 这就是所有文件的根目录
💡 什么叫"根目录"？
就像你电脑上的 C:\Users\你的用户名 或 /home/你的用户名 一样，
profile 就是整个项目存放文件的"大本营"。所有上传的文件都在这个目录下面。

这个配置被 XiziYiConfig 类读取，并且基于它生成了 13 个子目录，每个子目录对应一种业务用途：

XiziYiConfig 方法生成的完整路径用途
getProfile()/Users/.../uploadPath根目录
getUploadPath()/Users/.../uploadPath/upload通用上传
getSignPath()/Users/.../uploadPath/sign电子签名
getOriginalPath()/Users/.../uploadPath/original原始记录模板
getOriginalImgXcPath()/Users/.../uploadPath/original/xcImg现场检测图片
getOriginalImgSjPath()/Users/.../uploadPath/original/sjImg送检图片

每个接口的代码结构都一样

// 以通用上传为例（CommonController.uploadFile） @PostMapping("/upload") public AjaxResult uploadFile(MultipartFile file) throws Exception { String filePath = XiziYiConfig.getUploadPath(); // ① 拿到 "upload" 子目录 String fileName = FileUploadUtils.upload(filePath, file); // ② 执行上传 String url = serverConfig.getUrl() + fileName; // ③ 拼出完整URL返回前端 // 返回: url, fileName, newFileName, originalFilename }

3. 核心上传逻辑：FileUploadUtils

这是整个文件上传的"大脑"。upload() 方法做了四件事：

3.1 第一步：文件校验

校验项规则值
文件大小不能超过 DEFAULT_MAX_SIZE1024 MB (1GB)
文件名长度不能超过 DEFAULT_FILE_NAME_LENGTH100 个字符
文件类型后缀必须在白名单内bmp, gif, jpg, jpeg, png, svg, doc, docx, xls, xlsx, xlsm, ppt, pptx, pdf, html, htm, txt, rar, zip, gz, bz2, mp4, avi, rmvb
💡 还有个"守门员"——Spring Multipart 配置
在上面的校验之前，Spring 就已经拦了一道：
max-file-size: 1024MB（单个文件），max-request-size: 2048MB（一次请求总大小）

3.2 第二步：生成文件名（核心中的核心！）

文件名 = 日期目录 / 原始文件基名 _ 唯一ID . 后缀

拆开来看看每个部分是怎么来的：

部分来源示例值
日期目录DateUtils.datePath() → yyyy/MM/dd 格式2026/05/12
原始文件基名去掉后缀的文件名（如"检测报告.pdf" → "检测报告"）检测报告
唯一IDSeq.getId() → yyMMddHHmmss + "A" + 3位序号260512143025A001
后缀从文件名或 Content-Type 推断pdf
✅ 最终生成的相对文件名：
2026/05/12/检测报告_260512143025A001.pdf

3.3 Seq 唯一ID 是怎么生成的？

Seq.getId(Seq.uploadSeqType) 的组成： yyMMddHHmmss + "A" + 3位自增序号(000~999循环) 例如：2026年5月12日 14:30:25 → "260512143025" + "A" + "001" = 260512143025A001 序号从000开始，每次上传+1，到999后回到000重新开始。 这样即使同一秒上传多个文件也不会重名。

3.4 第三步：写入磁盘

// 拼接绝对路径 绝对路径 = baseDir + / + 相对文件名 = /Users/sunnicholas/uploadPath/upload + / + 2026/05/12/检测报告_260512143025A001.pdf = /Users/sunnicholas/uploadPath/upload/2026/05/12/检测报告_260512143025A001.pdf // 自动创建不存在的目录 if (!desc.getParentFile().exists()) { desc.getParentFile().mkdirs(); } // 写入文件 file.transferTo(Paths.get(absPath));

3.5 第四步：返回 Web 访问路径

// getPathFileName() 的返回值格式： /profile/{子目录}/{相对文件名} = /profile/upload/2026/05/12/检测报告_260512143025A001.pdf
💡 /profile 是什么？
它是一个"虚拟路径前缀"（定义在 Constants.RESOURCE_PREFIX），
前端拿这个路径拼上服务器地址就能访问文件了。
后端收到 /profile/... 的请求时，会自动把它映射到真实的磁盘路径。

4. 完整路径生成公式

磁盘绝对路径 =
{profile} / {子目录} / {yyyy/MM/dd} / {原始文件名}_{yyMMddHHmmss}A{3位序号}.{后缀}
Web 访问路径 =
/profile / {子目录} / {yyyy/MM/dd} / {原始文件名}_{yyMMddHHmmss}A{3位序号}.{后缀}

一条完整的上传链路

假设我上传了一个文件 "检定证书.pdf"： ① Controller 拿到文件，指定 baseDir = /Users/sunnicholas/uploadPath/cert ② FileUploadUtils 校验大小(OK)、类型(OK)、文件名长度(OK) ③ extractFilename() 生成新文件名: datePath = 2026/05/12 baseName = 检定证书 seqId = 260512143025A001 后缀 = pdf → "2026/05/12/检定证书_260512143025A001.pdf" ④ getAbsoluteFile() 拼绝对路径: /Users/sunnicholas/uploadPath/cert/2026/05/12/检定证书_260512143025A001.pdf 目录不存在 → 自动创建 ⑤ file.transferTo() 写入磁盘 ⑥ getPathFileName() 返回: /profile/cert/2026/05/12/检定证书_260512143025A001.pdf ⑦ Controller 拼 serverConfig.getUrl() + fileName 返回给前端

5. 其他上传方式

5.1 自定义文件名上传

// FileUploadCustomUtil.java —— 不自动生成名字，用你指定的文件名 FileUploadCustomUtil.uploadWithCustomName(uploadDir, file, "我的自定义名称.pdf"); // 跳过 extractFilename() 的自动命名逻辑，直接使用你给的文件名。

5.2 byte[] 方式写入

// FileUtils.writeBytes() —— 直接写二进制数据 String pathName = DateUtils.datePath() + "/" + IdUtils.fastUUID() + "." + extension; // 文件名是 UUID，不是原始文件名，用于不需要保留原始文件名的场景（如导入数据）。
⚠️ 两种方式的区别：
• FileUploadUtils.upload() → 文件名 = "原始名_SeqId.后缀" → 保留原始文件名，方便人识别
• FileUtils.writeBytes() → 文件名 = "UUID.后缀" → 纯UUID，不会中文乱码，适合系统内部使用

6. 设计思想总结

设计点怎么做的为什么
按日期分目录yyyy/MM/dd/ 作为文件路径前缀避免一个目录下积累几十万个文件，方便按天管理
文件名唯一加入 Seq（时间戳 + 机器码 + 序号）即使同名文件多次上传也不会覆盖
保留原始文件名文件名包含原始基名人看一眼就知道是什么文件，不用点开
多子目录隔离证书/签名/模板等分不同子目录按业务类型隔离，方便备份和清理
磁盘路径与URL分离磁盘存绝对路径，返回 /profile/ 前缀的URL隐藏真实磁盘结构，前端只认 URL，后端映射到磁盘
