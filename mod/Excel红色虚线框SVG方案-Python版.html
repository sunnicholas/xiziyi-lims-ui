一、为什么换成 Python？Java 方案为什么失败？

1.1 Java/POI 方案的致命问题

问题原因表现
边框颜色检测不稳定POI 的 XSSFCellStyle.getTopBorderXSSFColor() 在 PageOffice 保存后的文件中经常返回 null检测不到红色边框 → 回退旧 pipeline → 生成多张整页截图
检测到多余区域POI 读取合并单元格/隐藏单元格的边框时可能产生误判生成 page_1.png + page_2.png 两张（而非1张）
样式复制丢失cloneStyleFrom 跨 Workbook 复制时字体/边框/背景可能丢失截图排版错乱或内容丢失
降级链路复杂依赖 LibreOffice + POI + PDFBox 三层，每一层都可能失败错误难以定位

1.2 openpyxl 为什么更好

  • ✅ 直接访问 xlsx 的 XML 内部：cell.border.top.color.rgb 直接返回 "FFFF0000" 字串，无需类型转换
  • ✅ PageOffice 保存后的文件兼容：openpyxl 按 OOXML 标准解析，不受 PageOffice 的 xlsx 写入方式影响
  • ✅ 单进程即可完成所有操作：读取→检测→临时Excel→LibreOffice→SVG/PNG，全 Python 控制
  • ✅ 代码量少、可读性强：~200行 Python vs ~400行 Java

4.2 执行流程

1
openpyxl.load_workbook() 加载 Excel
读取所有 Sheet，获取单元格边框样式
2
is_red_dashed() —— 双条件判定
side.style in {'dashed', 'dashDot', ...} AND side.color.rgb == 'FFFF0000'
两个条件同时满足才是"红色虚线边框"
3
detect_regions() —— 矩形区域检测
扫描所有红色+虚线边框单元格 → 找 Top 边 → 向下匹配 Bottom 边 → 验证 Left/Right → 去重 → 最小尺寸校验
4
create_inner_workbook() —— 内裁剪（关键！）
跳过边框行/列：只复制 firstRow+1 ~ lastRow-1、firstCol+1 ~ lastCol-1 的单元格
这样创建的临时XLSX完全不含红色虚线边框，后续截图也不会有红框

LibreOffice XLSX→PDF(矢量) → pdf2svg PDF→SVG(矢量)

八、VBA 宏（确保红色虚线框正确）

在Excel模板中 Alt+F11 → 插入模块，粘贴以下代码。选中需要截图的区域后运行宏：

' codes fix from xzyPC: 选中区域 → 添加红色虚线边框
Sub AddRedDashedBorder()
    Dim s As Object
    For Each s In Array(xlEdgeLeft, xlEdgeTop, xlEdgeBottom, xlEdgeRight)
        With Selection.Borders(s)
            .LineStyle = xlDash        ' 虚线 ─ 必须是虚线不是实线
            .Color = RGB(255, 0, 0)    ' 红色 ─ 必须是红色不是黑色
            .Weight = xlMedium         ' 中等粗细（可选）
        End With
    Next
End Sub

' codes fix from xzyPC: 清除选中区域的红色虚线边框
Sub RemoveRedDashedBorder()
    Selection.Borders.LineStyle = xlNone
End Sub
⚠ 关键检查项
  1. 边框样式必须是 虚线（xlDash），不是实线（xlContinuous）
  2. 边框颜色必须是 红色（255,0,0），不是黑色
  3. 边框必须画在四个边（Left/Top/Bottom/Right）
  4. 框内至少留 1 行×1 列的内容区域（边框本身占2行×2列）
