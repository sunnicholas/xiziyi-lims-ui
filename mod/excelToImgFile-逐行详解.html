excelToImgFile() — 完整方法
    @param filePath  Excel文件路径
    @return 处理后的图片路径集合 + 数据页PDF路径
private Map<String, Object> excelToImgFile(String filePath) {
    Map<String, Object> resultMap = new HashMap<>();           // ① 准备返回容器
    File originalFile = new File(filePath);                  // ② 包装为File对象
    String parentDir = originalFile.getParent();                 // ③ 取父目录
    String resultImgDir = parentDir + File.separator + "result"; // ④ 拼result/子目录
    mkDir(resultImgDir);                                       // ⑤ 创建目录
    String dataPdfPath = FilePathUtil.getPdfPath(filePath, "_data");     // ⑥ 数据页PDF路径
    String resultPdfPath = FilePathUtil.getPdfPath(filePath, "_result"); // ⑦ 结果页PDF路径
    try {
        ExcelSheetToPdfUtils.convertSingleSheet(filePath, resultPdfPath, "结果页"); // ⑧ Excel→PDF(结果页)
        ExcelSheetToPdfUtils.convertSingleSheet(filePath, dataPdfPath, "数据页");   // ⑨ Excel→PDF(数据页)
        List<String> resultImages = PdfCertCleanConverter.convertPdfPages(           // ⑩ PDF→PNG
            resultPdfPath, resultImgDir);
        resultMap.put("croppedResultImages", resultImages); // ⑪ 装包：图片列表
        resultMap.put("dataPdfPath", dataPdfPath);           // ⑫ 装包：数据PDF路径
    } catch (Exception e) {
        throw new CustomException("Excel转图片处理失败", e);
    }
    return resultMap;  // 返回包裹
}

🔍 2. 逐行拆解（12步）

①

创建返回值 Map

好比准备一个快递纸箱，后面所有的处理结果（图片列表、PDF路径）都要装进这个箱子里，最后一起返回给调用方。

②

File originalFile = new File(filePath)

把字符串路径包装成 Java 的 File 对象。这只是个"指针"，并不会真的去打开文件。
例如："/home/xiziyi/uploadPath/original/2026/05/记录模板.xlsx"

③

originalFile.getParent() → 取父目录

从完整路径中去掉文件名，只保留目录部分。
输入：/home/xiziyi/uploadPath/original/2026/05/记录模板.xlsx
输出：/home/xiziyi/uploadPath/original/2026/05

④

拼出 "result/" 子目录路径

在父目录后面接上 /result。之所以用子目录而不是直接放同级，是为了避免文件名冲突、方便管理。
输出：/home/xiziyi/uploadPath/original/2026/05/result/

⑤

mkDir(resultImgDir) → 创建 result/ 目录

如果目录已经存在就跳过，不存在就创建。这步确保了后面 PDF→PNG 时输出路径是确实存在的。
底层用的是 Files.createDirectories()，会自动创建中间所有不存在的父目录。

⑥⑦

用 FilePathUtil.getPdfPath() 生成两个 PDF 路径

这个工具方法的逻辑很简单：去掉Excel的扩展名，换上 PDF 扩展名，中间加个后缀。

输入：/home/.../记录模板.xlsx，后缀 "_result"
输出：/home/.../记录模板_result.pdf

输入：/home/.../记录模板.xlsx，后缀 "_data"
输出：/home/.../记录模板_data.pdf

⑧

ExcelSheetToPdfUtils.convertSingleSheet(filePath, resultPdfPath, "结果页")

这是第一步转换的核心——Excel → PDF。它做了三件事：

  1. 用 Apache POI 打开 Excel，遍历所有单元格：公式→静态值（因为LibreOffice不计算公式）
  2. 删除"结果页"以外的所有其他 Sheet（只保留目标Sheet）
  3. 把处理后的临时Excel交给 LibreOffice，由它打开后 → "另存为PDF"

输出文件：/home/.../记录模板_result.pdf

⑨

ExcelSheetToPdfUtils.convertSingleSheet(filePath, dataPdfPath, "数据页")

和上一步完全一样的逻辑，只是目标是 "数据页" Sheet → 记录模板_data.pdf

⑩

PdfCertCleanConverter.convertPdfPages(resultPdfPath, resultImgDir)

这是第二步转换的核心——PDF → PNG。注意：只转换了 "结果页"的PDF，数据页PDF不转。它做了：

  1. 用 PDFBox 打开 记录模板_result.pdf
  2. 逐页以 600 DPI（打印级超清）渲染成 Java 位图
  3. 对每张位图执行 智能裁剪（去上下左右空白区域）
  4. 写出到 result/ 目录：page_1.png、page_2.png...
  5. 返回全部 PNG 文件的路径列表

返回值示例：["/home/.../result/page_1.png", "/home/.../result/page_2.png"]

⑪⑫

装包 + 返回

把两个东西塞进 Map：

KeyValue说明
"croppedResultImages"图片路径列表如 [".../page_1.png", ".../page_2.png"]
"dataPdfPath"PDF路径字符串如 "/home/.../记录模板_data.pdf"

这个 Map 交回给 saveOriginalFile() 后，图片列表序列化成 JSON 存入数据库的 result_file_url 字段，PDF 路径存入 data_pdf_url 字段。

❓ 3. 核心问答：为什么不直接 Excel → PNG？

用户的问题：
程序的执行逻辑是将 Excel 先转化为 PDF，然后再转化为图片（PNG）。为什么是多此一举？为什么不能直接把 Excel 转成 PNG？

答案有三个层次：技术限制 + 格式保真 + 业务需要

  1. 层次一：Java 生态里不存在免费且高质量的 "Excel → PNG" 方案

    Java 库能直接 Excel→PNG？为什么不行 / 什么代价
    Apache POI ❌ 完全不行 POI 只是一个数据读写工具。它能读单元格里的数字、文字、公式，但它不会"画"表格。合并单元格、边框、颜色、字体——这些东西 POI 只能存、不能渲染成一幅画。
    Aspose.Cells ✅ 可以 但是商业付费库。注意代码中有这行：
    // AsposeLicenseUtil.getLicense(); —— 被注释掉了！说明服务器上没有付费 License，或者为了省钱没有用它。
    LibreOffice Calc ❌ 不能 LibreOffice 的 Calc 组件可以 Excel→PDF，但是没有直接的 Excel→PNG 命令行选项。它能输出 PDF、HTML、CSV，但不能直接输出 PNG。

    所以设计者的选择是：要么花钱用 Aspose，要么免费组合 LibreOffice + PDFBox。显然选了后者。

  2. 层次二：LibreOffice 是唯一能做到 "Excel 1:1 格式还原" 的免费方案

    LibreOffice 的 Calc 是一个真实的电子表格软件，不是简单的格式转换器。它打开 Excel 后能做到：

    ✅ 合并单元格✅ 边框样式（粗细/颜色/虚线）✅ 字体/字号/颜色
    ✅ 条件格式✅ 数字格式（日期/货币）✅ 行高/列宽
    ✅ 单元格背景色✅ 文字对齐方式✅ 打印区域/分页

    但 LibreOffice 的"文件→导出"功能只支持 PDF 输出，不支持 PNG。所以 PDF 成了必经的中间产物。

  3. 层次三："中间产物" PDF 不是废品，它在业务中还有用

    注意方法返回了两个东西：

    excelToImgFile()
      ├── 结果页PDF → PdfCertCleanConverter → PNG × N 张 → 嵌入证书Word模板的结果页位置
      └── 数据页PDF → 直接保留！不转图片！ → 后续"证书编制"中和主页合并成完整档案PDF

    认证检测机构的档案必须是 PDF 格式（盖电子章、防篡改）。如果在第一步就把 Excel 全转成了 PNG，那数据页就只剩图片，没法合并到最终证书 PDF 里了。

一句话总结：
Excel → PDF（LibreOffice）→ PNG（PDFBox）不是"多此一举"，而是技术上的最优解——用免费的 LibreOffice 保证格式还原，用 PDFBox 实现高清图片，中间的 PDF 顺便还给后续"证书合并"留着用。
