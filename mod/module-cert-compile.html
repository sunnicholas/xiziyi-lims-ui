📜 证书编制

上一环节：记录编制（审核通过后）→ 证书编制（生成证书+编号）→ 下一环节：证书审核 → 打印/发放

1. 模块概述

证书编制是整个 LIMS 系统的核心交付物环节。根据检测/校准结果生成正式的检定证书或校准证书，包括证书编号生成、Word 模板填充、证书图片合成、防伪码生成等功能。

📌 前端页面：views/establishment/CertificateEstablish/index.vue（证书列表）
📌 编辑组件：components/pageoffice/ZSadd.vue、ZSupdate.vue
📌 权限标识前缀：measure:testTaskAllot（与记录编制共用Controller）
📌 核心Controller：TestTaskAllotController.java（与记录编制共用）

3. 证书编号生成（核心功能）

代码位置：TestTaskAllotController.java 的 getOrGenerateCertNumber() 方法（L462）

3.1 编号规则分类

类型格式示例触发条件
CMA类型 XZYJC + 年份(4位) + 递增数(4位) + 专业代码 XZYJC20260001JJG 专业为"机械"或"其他"（cmaFlag=true）
非CMA 检定 科室 + 委托类型(S/X) + 专业 + 证书类型 + 报告类型(G) + 年月(4位) + 递增(5位) LXSEJJG260400001 entrustTwoLevel=1（检定）
非CMA 校准 科室 + 委托类型 + 专业 + 证书类型 + 报告类型(F) + 年月 + 递增 LXSCJJF260400001 entrustTwoLevel=2/3（校准）
非CMA CNAS 科室 + 委托类型 + 专业 + 证书类型 + 报告类型(C) + 年月 + 递增 JJGSHXC260400001 entrustTwoLevel=5（CNAS）

3.2 编号生成核心逻辑

// TestTaskAllotController.getOrGenerateCertNumber() // 1. CMA类型编号 String currentYear = DateUtils.parseDateToStr("yyyy", new Date()); String increment = configService.incrNumber("cma_zs", 4, "_no"); testPost = "XZYJC" + currentYear + increment + classifyInfo.zyCode; // 2. 非CMA类型编号 testPost = String.join("", ksCode, wtCode, zyCode, certCode, reportCode); return configService.getZsCode(testPost, null, entrustTime, 5); // → 内部调用 incrZsNumberStr() → Redis INCR 原子递增 → 每月自动重置 // Redis Key格式: MEASURE:{pre}:incr:{entrustTime} // 返回格式: LXSEJJG260400001

4. 证书图片上传合成（重点）

代码位置：TestTaskAllotController.uploadCertImgBatch()（L732-L860）

// POST /measure/testTaskAllot/uploadCertImgBatch // 传参: allotId, certFilePath(证书文件路径), // deviceTag(设备书签标识), files[](图片文件数组) 核心逻辑: 1. 获取证书 Word 文件路径 (certFilePath) 2. 遍历上传的图片文件，保存到临时目录 3. 使用 Aspose.Words 打开 Word 模板 4. 根据 deviceTag(书签名称) 定位 Word 中的书签位置 5. 将图片插入/替换到书签位置（如设备图片、签名图片等） 6. 保存新的 Word 文件 7. 可选：将 Word 转换为 PDF 8. 清理临时文件 文件路径: {profile}/cert/{entrustId}/{allotId}/证书.docx
⚠️ 图片合成关键依赖：
  • Aspose.Words (aspose-words-15.8.0.jar) — Word 操作核心
  • Spire.Xls — Excel 转换支持
  • license.xml — Aspose 许可证文件（否则有水印）
