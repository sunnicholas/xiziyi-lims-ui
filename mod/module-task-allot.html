📋 任务分配

上一环节：业务流转 → 任务分配（分配检测人员 + 分发样品）→ 下一环节：记录编制

1. 模块概述

委托单审核通过并经过业务流转后，由检测部部长或科室主任将检测任务分配到具体的检测员（分配样品和检测项目），检测员确认流转后开始做实验。

📌 涉及角色：检测部部长/科室主任（分配任务）、检测员（确认流转）
📌 权限标识前缀： measure:testTaskInfo
📌 前端页面： xiziyi-lims-web/src/views/taskallot/testTaskInfo/index.vue

2. 前端实现

API 封装文件：xiziyi-lims-web/src/api/taskallot/testTaskInfo.js

GET/measure/testTaskInfo/list任务分配列表（分页）
GET/measure/testTaskInfo/{taskId}任务详情
POST/measure/testTaskInfo确认流转
POST/measure/testTaskInfo/batchAllot批量任务分配
GET/measure/msSpecialTestTask/taskList特种设备任务列表
POST/measure/msSpecialTestTask/updateInstructBook更新指令书

4. 核心SQL

-- 查询待分配的检测任务 SELECT ti.*, et.entrust_no, si.sample_name, mi.item_name FROM test_task_info ti LEFT JOIN ms_entrust_task et ON ti.entrust_id = et.id LEFT JOIN ms_sample_info si ON ti.sample_id = si.id LEFT JOIN bas_meterage_item mi ON ti.item_id = mi.id WHERE ti.allot_status = '0' -- 未分配 ORDER BY ti.create_time DESC -- 批量任务分配 INSERT INTO test_task_allot (allot_id, entrust_id, template_classify_id, user_id, task_id, create_time) VALUES (?, ?, ?, ?, ?, sysdate())

5. 核心数据表

表名说明核心字段
test_task_info检测任务信息表（每个检测项目一行）task_id(主键), entrust_id(委托ID), sample_id(样品ID), item_id(检测项目), allot_status(分配状态:0未分配/1已分配), flow_status(流转状态)
test_task_allot任务分配表（核心）allot_id(主键), entrust_id, template_classify_id(模板分类), user_id(分配给谁), task_id(任务ID) → 这条记录就是后续编制、出证书的基础！
💡 关键理解：任务分配是整个流程的枢纽。分配后产生 test_task_allot 记录，后续的记录编制和证书编制都是围绕 allot_id 进行的。
