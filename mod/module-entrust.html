📝 委托登记下单

业务流程图：委托下单 → 委托审核 → 客户签名 → 业务流转 → 任务分配

1. 模块概述

委托登记是整个检测业务流程的起点。客户委托检测/校准服务，由业务员在系统中创建委托单，填写委托方信息、样品信息、检测项目，生成委托协议，客户签名确认后进入业务流转环节。

📌 涉及角色：业务员（登记）、业务部部长/审核员（审核）、客户（签名）
📌 权限标识前缀： measure:msEntrustTask
📌 前端页面： xiziyi-lims-web/src/views/business/acceptance/index.vue

4. 委托创建核心逻辑

4.1 新增委托 - POST /measure/msEntrustTask

传参：@RequestBody MsEntrustTask（含委托方信息、样品列表、检测项目等完整数据）

// MsEntrustTaskController.java add() → 调用 msEntrustTaskService.insertMsEntrustTask() // MsEntrustTaskServiceImpl.insertMsEntrustTask() 核心步骤: 1. 生成委托编号(entrust_no)：根据规则生成唯一编号，如 "XZYWT202604290001" 2. 保存委托主表: INSERT INTO ms_entrust_task (...) 3. 保存样品明细: 批量 INSERT INTO ms_sample_info (entrust_id, sample_name, spec, ...) 4. 生成委托单文件(Word/PDF): - 使用 Aspose.Words 或 PageOffice 处理模板 - 根据模板路径和数据填充书签/占位符 - 生成的委托单保存到: uploadPath/entrust/{日期}/{entrustId}/委托单.docx - 更新 entrust_path 字段 5. 生成二维码: 在委托单上嵌入防伪二维码 6. 保存操作记录: INSERT INTO ms_entrust_record

5. SQL 关键查询

5.1 委托列表查询

-- 查询委托登记列表 (MsEntrustTaskMapper.xml) SELECT e.*, c.customer_name, (SELECT COUNT(1) FROM ms_sample_info WHERE entrust_id = e.id) AS sample_total FROM ms_entrust_task e LEFT JOIN crm_customer c ON e.customer_id = c.id WHERE e.del_flag = '0' AND e.entrust_no LIKE CONCAT('%', #{entrustNo}, '%') AND e.status = #{status} AND e.customer_id = #{customerId} ORDER BY e.create_time DESC

5.2 业务流转列表查询

-- businessFlowList: status=20(已提交), signStatus=1(客户已签名) SELECT e.* FROM ms_entrust_task e WHERE e.status = '20' AND e.sign_status = '1' ORDER BY e.create_time DESC

6.2 重新生成委托单

GET /measure/msEntrustTask/createQuotedEntrust?entrustId={id}

使用 Spring 事件监听机制异步处理，确保数据库事务一致性：

// MsEntrustTaskController.createQuotedEntrust() publisher.publishEvent(new EntrustProcessEvent(entrustId, loginUser, status)); // EntrustProcessListener 监听到事件后异步执行: // 1. 重新查询委托数据和样品数据 // 2. 使用 Aspose.Words 重新填充模板 // 3. 覆盖原有文件 // 4. 更新 entrust_path
⚠️ 常见问题排查：
  • 委托单生成失败 → 检查模板文件是否存在、Aspose license是否有效
  • 路径问题 → Linux/MacOS 路径分隔符是 "/"，Windows 是 "\"
  • 二维码不显示 → 检查 ZXing 依赖和字体文件
